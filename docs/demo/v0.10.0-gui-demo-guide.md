# GeoTaskShield v0.10.x GUI 演示指南

本文档用于演示 `v0.10.0` 和 `v0.10.1` 发布包中的 GUI 主流程。演示重点是 Phase 13 固化后的真实 LLM provider 产品化体验：默认本地规则分析、可选 OpenAI-compatible provider、后台分析、超时配置、缺 key fallback 和 provider 状态提示。`v0.10.1` 是发布卫生补丁，不改变 GUI 演示流程。

## 1. 启动 GUI
```powershell
cd D:\VS2026_Projects\GeoTaskShield
```
从源码构建目录启动：

```powershell
out\build\x64-debug-qt\GeoTaskShield\GeoTaskShieldGui.exe
```

从发布包启动：

```text
out\package\GeoTaskShield-v0.10.1-windows-x64\GeoTaskShieldGui.exe
```

发布包中应包含：

- `GeoTaskShield.exe`
- `GeoTaskShieldAgentDemo.exe`
- `GeoTaskShieldBatchDemo.exe`
- `GeoTaskShieldGui.exe`
- `phase5_batch_results.csv`
- `phase5_batch_report.md`
- `README.md`
- `HANDOFF.md`
- `CHANGELOG.md`
- `docs\demo\v0.10.0-gui-demo-guide.md`

## 2. Simulation Tab

1. 打开 `Simulation` tab。
2. 保持默认参数，点击 `Run Simulation`。
3. 确认地图显示 worker、暴露位置、task、assignment 连线和图例。
4. 确认右侧指标刷新，底部日志显示仿真完成。

## 3. Batch Results Tab

1. 打开 `Batch Results` tab。
2. 点击 `Open CSV`，加载 `phase5_batch_results.csv`。
3. 使用 Privacy / Algorithm 下拉框筛选。
4. 使用 Metric 下拉框切换 `completionRate`、`privacyUtilityRatio`、`fairnessIndex`、`averagePrivacyLoss`。
5. 点击表头验证数值列排序。
6. 点击 `Export Filtered CSV` 导出当前筛选 CSV。
7. 点击 `Preview Markdown` 预览当前结果报告。
8. 点击 `Export Markdown` 导出当前结果 Markdown。

## 4. Agent Assistant 默认本地分析

1. 先在 `Batch Results` tab 加载 `phase5_batch_results.csv`。
2. 打开 `Agent Assistant` tab。
3. 确认 provider 为 `Local rule-based`。
4. 输入：

```text
Compare privacy mechanisms for 50 tasks and explain completion rate, privacy utility, privacy loss, and fairness.
```

5. 点击 `Analyze`。
6. 确认 provider 状态显示本地分析完成。
7. 确认 `Parsed intent` 显示结构化意图。
8. 确认 `Markdown analysis` 包含：
   - Best completion rate
   - Best privacy-utility ratio
   - Lowest average privacy loss
   - Best fairness index
   - Next Experiment Suggestions
9. 点击 `Export Markdown` 导出分析报告。

## 5. Optional OpenAI-compatible Provider

真实 provider 只在用户显式选择 `OpenAI Compatible` 后调用。默认本地 provider 不需要网络和 API key。

### 5.1 缺 key fallback 演示

1. 确保当前进程没有配置 `GTS_LLM_API_KEY` 或 `DASHSCOPE_API_KEY`。
2. 在 `Agent Assistant` tab 选择 `OpenAI Compatible`。
3. 输入任意分析请求并点击 `Analyze`。
4. 确认 GUI 不阻塞，Analyze 按钮在运行中短暂禁用。
5. 确认 provider 状态显示 unavailable / fallback。
6. 确认 Markdown 预览显示 `LLM Provider Unavailable` 和 `Local Analysis Fallback`。

### 5.2 真实 provider 配置

如需真实调用 OpenAI-compatible 服务，在启动 GUI 前设置环境变量。默认 base URL 是 DashScope compatible endpoint：

```powershell
$env:GTS_LLM_API_KEY = "<your API key>"
$env:GTS_LLM_MODEL = "deepseek-v4-flash"
$env:GTS_LLM_BASE_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1"
$env:GTS_LLM_TIMEOUT_MS = "15000"
```

注意：

- API key 只允许保存在本机运行时环境变量中。
- 不要把 API key 写入源码、README、HANDOFF、demo guide、报告、CSV 或 git commit。
- `GTS_LLM_TIMEOUT_MS` 为毫秒，非法值会回退到默认配置。
- 旧 `DASHSCOPE_*` 环境变量仍作为兼容 fallback；当 `GTS_LLM_*` 和 `DASHSCOPE_*` 同时存在时，优先使用 `GTS_LLM_*`。
- provider 请求在后台线程运行，避免阻塞 Qt GUI。
